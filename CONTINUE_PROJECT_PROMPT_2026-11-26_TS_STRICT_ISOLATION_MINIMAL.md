# Продолжение GPM и переноса TS с другого компьютера

Снимок от 26.11.2026. На другом компьютере открой этот файл из GitHub, прочитай [правило владельца](AGENTS.md) и [навык проекта](.agents/skills/gpm-application/SKILL.md). Восстанови доступ только к нужному контуру со строгой проверкой SSH-отпечатка. Основная CRM `workstaffcrm.ru` полностью исключена из работ и проверок, включая чтение. Все работы, тесты и интеграционные проверки с CRM выполняются только в TS.

**Приложение GPM.** Последние выпуски уже установлены. Готовы нормализация телефонов без переписывания номеров в CRM, упрощение чата, отдельная повторная модерация опубликованных заявок и QR бригады через назначение старшего в TS. Логисты #4 и #5 уже созданы. Дальше ручная приемка входа и ID логистов, повторной модерации, прихода и ухода по QR на телефонах с камерой и GPS. Рабочая SMS-регистрация остается отдельным этапом. Детали в [кратком статусе приложения](PROJECT_HANDOFF_2026-11-24_SESSION_MINIMAL.md), границы брать из актуального `AGENTS.md`.

**Перенос TS.** Старая TS работает, DNS и ее обмен остаются на прежнем месте. Закрытый кандидат на PHP 8.5 и MySQL 8.4 подготовлен. Прошли 23 сценария, контрольные суммы 72 таблиц после тестов совпали. Данные кандидата предварительные, ручная приемка еще нужна. Ключ резервной копии сохранен у владельца и проверен, серверная копия сохранена. С другого компьютера помочь повторно скачать ключ по просьбе владельца через проверенное подключение.

Следующий шаг по переносу — прочитать частные `RECOVERY.json`, `state.json` и квитанции **в контуре TS**. Подобрать независимый входящий контур TS. До согласования окна и способа переключения старая TS продолжает принимать записи. После согласования понадобятся свежие файлы и данные только TS, проверенный переход MySQL 5.7 → 8.0 → 8.4, сверка 72 таблиц и единственный активный обмен. Для MySQL использовать явно заданный TS `defaults-file`. Сохранить `+03:00`, две согласованные nullable-колонки `activity_log`, ключи приложения, аккаунты, ID, аудит и обычные email-коды. Общие миграции, scheduler, фоновые очереди, деловую почту и дебиторку не включать. DNS TS меняет владелец после приемки. Старый сервер и резервные копии сохранять. Перед удалением источника нужна независимая копия зашифрованных архивов.

В Git хранится только этот краткий статус и правило. Полная переписка, закрытые квитанции, доступы, ключи, данные и частные пути остаются в закрытом контуре. Рабочую копию проекта на C: не создавать.
