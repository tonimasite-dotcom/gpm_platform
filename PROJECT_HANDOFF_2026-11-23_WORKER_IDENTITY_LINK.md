# Постоянная связь исполнителей GPM/TS: подготовка

23.11.2026 владелец поручил автоматическое сопоставление исполнителей по телефону:
одна существующая карточка рабочего — связать, нет — создать, дубли — разбор.
После первичного сопоставления хранить постоянную пару внутренних ID.
CRM должна остаться внешне как сейчас: привычные рабочие и бригадир, без
возврата отдельной панели онлайн-табеля и ручной привязки профилей на заявке.

## Фактический результат

Черновой PR #33, ветка work/worker-identity-link-2026-11-23.
Подготовлена чистая PHP-политика GpmWorkerMatchPolicy и синтетические проверки.
QA 45227287473 success: PHP lint и сценарии сопоставления, международные номера,
неподтвержденный/тестовый телефон, дубли, ролевые конфликты, неактивная карточка,
сохранение связи при смене номера. Рабочего серверного обмена в PR пока нет.

Выяснено: production-регистрация пока по приглашениям; телефон в профиле
не подтвержден реальным каналом. Отдельная анкета registration-preview
с кодом 123456 — лаборатория, а не доказательство владения номером.
Вопрос владельцу о выборе SMS либо кода входящим звонком ожидает ответа,
если он не дан последующим сообщением. Независимая логика подготовлена,
но автоматические записи по непроверенному телефону не включать.

Рабочие системы и их интерфейсы этим этапом не менялись.
Предыдущий откат только TS остается в силе: GPM PR #32 оставлен, TS-адаптер
табеля снят; его снимок для возврата сохранен. Не возвращать его вместо
новой постоянной связи без отдельной просьбы владельца.

## Следующий шаг

[План и ограничения](integrations/workstaff-test-crm/worker-link/PLAN.md).
Решить реальное подтверждение телефона, затем подготовить постоянное хранилище,
идемпотентный серверный обмен и проверки на тестовых БД. Фоновые изменения
карточек не должны менять пароли, роли, деньги, старые часы и историю.
До реальной миграции согласовать ее точную схему и последствия, backup и откат.
Сам телефон используется для начального поиска, не как изменяемый постоянный ID.

Основную CRM не трогать. Разработка/испытания только TS.
Очистка заявок не разрешает удаление схемы, аккаунтов, авторизации, аудита,
конфигурации, секретов, backup и инфраструктуры. Жизненно важные компоненты
и рабочие данные этим этапом не менялись. Локаторы и пользовательские сведения
в публичный Git не помещать. Работать без копий проекта на C: через GitHub/Actions.
