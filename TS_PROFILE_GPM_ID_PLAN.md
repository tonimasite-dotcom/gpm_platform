Ручной ID GPM в профиле TS

Только TS. В своем профиле и карточке пользователя поле «ID в приложении» доступно для ролей «Логист» и «Администратор». Значение копируется из профиля сотрудника GPM, проверяется и сохраняется вручную. Сохраненный ID подставляется при отправке заявки, его можно очистить. Регистрация пользователя CRM не создает аккаунт GPM и не выдает ID.

Выдача ID в GPM остается прежней: при регистрации по доверенному корпоративному приглашению. У сторонних логистов ID и карточки ID нет. Новых изменений GPM для этой задачи не требуется.

Для хранения подготовлена одна необязательная колонка TS. Перед применением миграции требуется отдельное согласование владельца по AGENTS.md; рабочая схема пока не меняется. Проверять только эту миграцию, общий набор миграций не запускать. Откат кода сохраняет колонку и введенные ID.

Права редактирования проверяются сервером. Неизвестный или неактивный ID отклоняется. Ошибка GPM не меняет сохраненное значение; неизмененный ID и его очистка не требуют сети. Номера заявок, телефоны, пароли, роли и вход сохраняются. Основную CRM не менять. Дебиторку, рассылки, scheduler и очереди TS не включать; обычные email-коды и отдельный обмен GPM сохранить.

Закрытая подготовка, сборка, проверки и пакет выполняются только на разрешенном сервере TS; исходники, SDK и архивы на клиентский ПК не возвращать. Персональные данные, служебные локаторы и закрытые отчеты в публичный Git не добавлять.
