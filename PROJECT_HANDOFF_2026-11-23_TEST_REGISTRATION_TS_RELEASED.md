## Поведение

В отдельной registration-preview код 123456 действует для всех тестовых участников.
После завершения новой анкеты серверный обмен ищет рабочего TS по полному
нормализованному личному телефону. Один рабочий — постоянная связь с его ID;
нет совпадения — новая тестовая карточка; дубли/удаленная карточка/сотрудник
или администратор/чужая связь — разбор без автоматического объединения.
Существующие данные, роли, пароли, активность, банковские реквизиты и деньги
не перезаписываются тестовой анкетой.

Новые карточки получают только роль рабочего и примечание о тестовой регистрации.
Пароль CRM не создается, письма/SMS не отправляются. Для повторяемости новых
тестовых карточек используется уникальный технический email в домене .invalid.
Филиал — точная компания «Джи Пи ЭМ» по городу, без смешивания с другими компаниями.
При неоднозначности филиала запись откладывается. Закрытые квитанции сохраняют
постоянную пару тестовый profile ID / users.id, без ручных привязок на заявке.

Тестовый профиль не является аккаунтом/JWT основного GPM. Production-политика
по-прежнему не принимает test_code как реальное подтверждение владения телефоном.
Рабочая регистрация по SMS и связь настоящих аккаунтов GPM — следующий этап.
Полная карта полей анкеты/CRM еще не подключена; отсутствующие поля, например пол,
не придумываются. Тестовый этап создает карточку из ФИО, телефона, даты рождения
и города либо связывает существующую, без перезаписи ее анкеты.
Перенос состава/старшего и QR-отметок в существующий CRM-табель этим выпуском
не добавлялся. Не выдавать этот тестовый этап за полную production-синхронизацию.

Начальная дата испытания зафиксирована при установке. Более старые завершенные
анкеты автоматически не импортируются; для их переноса сначала нужен пробный разбор.
При обычной работе используется ближайший запуск ежеминутного обмена.
Проблемы повторяются с задержкой, обычные заказы выполняются первыми.
