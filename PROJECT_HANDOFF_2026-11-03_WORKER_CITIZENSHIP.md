# GPM: гражданство исполнителя, 03.11.2026

## Изменения

- Блок гражданства и пояснение о логисте убраны из профиля исполнителя.
- При регистрации по приглашению рабочий выбирает «Гражданство РФ: Да / Нет».
  Значения по умолчанию нет; выбор обязателен. У клиента и логиста поля нет.
- API проверяет фактическую роль приглашения, сохраняет гражданство в профиле
  в одной транзакции с аккаунтом. Схема БД не меняется.
- Существующий отбор заявок по гражданству сохранен. Рабочий не может изменить
  сохраненное гражданство; логист может через существующий редактор.
- Старые профили без гражданства могут сохранять остальные поля. Их гражданство
  задает логист. Обращение в помощь пока не добавлено.
- Правило владельца: простые правки после проверок сразу выпускать в production,
  без повторного запроса подтверждения; фиксировать Git, README и handoff.
  Правило закреплено в AGENTS.md и PRODUCTION_DEPLOYMENT.md.

## Границы и продолжение

Основную CRM никогда не изменять без отдельного предварительного явного
согласования владельца. Задача по GPM и упоминание CRM не являются согласием.
Действующая интеграция ограничена ts.workstaffcrm.ru. В этой задаче никакая CRM
не изменялась и не деплоилась.

Очистка данных не разрешает DROP/TRUNCATE, удаление таблиц, схемы, миграций,
кода, аккаунтов, профилей, авторизации, приглашений, аудита, конфигурации,
секретов, backup/rollback, workflows или инфраструктуры. Для таких изменений
нужны отдельная задача, точный перечень, оценка последствий, план восстановления
и явное согласование. В этой задаче по прямому запросу владельца меняется поток
регистрации и сохранения гражданства; существующие аккаунты и профили, схема,
секреты, инфраструктура и механизмы восстановления не меняются.

После выпуска владелец проверяет отсутствие блока в профиле и форму регистрации.
Ручную регистрацию в рабочей БД агент не выполняет. Старые замечания ручной
приемки от 15/21 октября и отложенные Telegram backup alerts остаются отдельно.
