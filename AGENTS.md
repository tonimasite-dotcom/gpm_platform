# Правила работы с GPM

- Правило владельца от 11.11.2026: каждый snapshot сессии и промпт продолжения
  обязательно сохранять в GitHub, чтобы новый чат мог получить их оттуда.
  Промпт/handoff/индекс с SHA фиксировать в Git и отправлять в ветку проекта;
  приватные данные, БД, переписку, вложения и внутренние отчеты хранить только
  зашифрованными assets Release. Ключи отдельно, не в Git и не в архивах.
  Сохранение не считать завершенным до проверки наличия файлов в GitHub,
  контрольных сумм и тестового скачивания. В ответе давать точные GitHub-ссылки
  на промпт и комплект; локальный снимок без GitHub не завершает поручение.

- Последнее строгое уточнение владельца от 11.11.2026: ВСЕ работы и приватные
  проверки выполнять ТОЛЬКО на старом сервере TS (5.183.191.222). Новый сервер
  основной (5.188.30.25) разрешено ТОЛЬКО читать: никаких записей, копий,
  backup-файлов, приватных БД, запусков приложения/заданий и изменений служб.
  Не переносить TS или DNS на новый сервер. Ранее созданные там закрытые
  каталоги оставить по явному поручению владельца; ничего не удалять.
  Владелец сказал «стоп»: работа остановлена, до нового продолжения только
  сохранение локальной точки продолжения. Это уточнение отменяет прежний
  план подготовки/восстановления приватной TS на новом сервере.

- Писать кратко и по делу. Использовать е вместо буквы с двумя точками.
- По поручению владельца от 03.11.2026 простые правки после проверок сразу
  публиковать в рабочее приложение через штатный production workflow.
  Дополнительное подтверждение такого выпуска не требуется. Задача завершена
  после успешного deployment и проверки результата, а не после локальной правки.
- Перед выпуском проверить свежую успешную резервную копию и пройти проверки
  по затронутым компонентам. Сложные изменения, миграции и операции с рабочими
  данными требуют отдельного согласования объема и последствий.
- Фиксировать изменения в Git, текущий статус в README, детали выпуска и точку
  продолжения в новом PROJECT_HANDOFF. Указывать commit кода, CI/deploy/backup,
  результаты проверок, остаток ручной приемки и границы затронутых систем.
- Строгое правило владельца от 06.11.2026: пока работаем только с
  ts.workstaffcrm.ru. Основную CRM вообще не трогать до завершения всех тестов
  и проверки синхронизации; переход к ней требует отдельного явного согласования.
  Задача по GPM не разрешает менять основную CRM.
- Отдельное поручение владельца от 06.11.2026 разрешает read-only сверку
  основной CRM с ts перед продолжением тестов. Это разрешение только на аудит:
  без правок файлов/настроек/БД, запуска заданий и переноса данных основной CRM.
- После сверки владелец подтвердил объем обновления только ts: актуальная общая
  функциональность, сохранение GPM/редактора ставки/ограничений логиста, учетных
  записей, настроек и данных ts; допустима короткая остановка. Данные и секреты
  основной не копировать. Конкретные последствия миграций и восстановления
  разобрать в плане и репетиции до применения. Ответы коллег по синхронизации
  уже есть, но оставлены отдельной задачей; не считать их отсутствующими и
  не включать новые правила обмена в обновление ts.
- Очистка заявок не разрешает удаление таблиц, схемы, кода, аккаунтов, профилей,
  авторизации, приглашений, аудита, конфигурации, секретов, backup и инфраструктуры.
  Для изменения жизненно важных компонентов нужны отдельная задача, перечень
  объектов, оценка последствий, план восстановления и явное согласование.
- Уточнение владельца 09.11.2026 сужает прежний объем общей доводки ts:
  воспроизвести состояние только затрагиваемых настроек/опций и их необходимых
  зависимостей, чтобы проверить изменения перед будущим переносом на основную.
  Полная работоспособность всех функций ts не обязательна. Cron-задачи не переносить;
  включение/доводка всех фоновых автоматов не входит в этап. Приемка ограничена
  затронутыми сценариями, сохранностью данных/прав, совместимостью и откатом.
  Посторонние найденные дефекты и уже подготовленные дополнительные исправления
  не включать автоматически в итоговый пакет. Основная CRM остается без изменений
  до отдельного явного согласования; это уточнение не разрешает ее выпуск.
- В новых handoff и continuation prompt повторять два предыдущих ограничения
  и указывать, затронуты ли основная CRM и жизненно важные компоненты.
- Новое поручение владельца 10.11.2026 расширяет прежнее сужение для заявок:
  проверить все поля/поведение заявок основной и привести заявки TS к тому же
  состоянию. Это не разрешает перенос всей CRM, cron, секретов или рабочих данных
  основной. Связанные расчеты/касса/документы и изменение срока редактирования
  требуют конкретного плана, репетиции и согласования последствий по общему правилу.
  Сохранять TS/GPM, debt-off, демозащиту и обычные email-коды входа.
- Последующее явное подтверждение владельца 10.11: по заявкам TS должен быть
  копией основной и визуально, и по логике, включая описанные связанные расчеты,
  кассу/выплаты, документы и срок редактирования. TS-only поля/виджеты убрать из
  интерфейса; это не разрешает удалять колонки/таблицы/аккаунты и инфраструктуру.
  Не запрашивать этот же объем повторно. Основная остается только read-only.
  По просьбе владельца работа безопасно остановлена для перехода в новый чат;
  до нового продолжения разрешены только сохранение и проверка snapshot.
- Последнее уточнение владельца: основную CRM сейчас разрешено ТОЛЬКО читать
  для сравнения; никаких ее правок/запусков заданий/переноса данных. Проверять
  приложение пока в связке с ts. Ежедневные email-рассылки на ts должны всегда
  оставаться отключенными, остальные побочные функции — демо. Уточнение владельца
  10.11: обычные коды входа оставить на email, без изменений контроллера входа/JWT.
  На 10.11 TS demo-06 установлен (c4e5ef2, CI 42802391274, deployment PASS):
  четыре запрета дебиторки сохранены, деловая почта заблокирована, код входа
  использует отдельный SMTP-mailer. Владелец подтвердил получение email-кода.
  Сквозная приемка приложения еще остается ручной проверкой; не объявлять ее пройденной.
- Секреты, пароли и незашифрованные резервные копии не публиковать в Git и логах.
