# TS: ID в профиле обязателен для отправки — 23.11.2026

Уточненное правило владельца опубликовано: перед отправкой заявки логист или администратор обязан сохранить ID приложения в своем профиле TS. При отправке ID автоматически подставляется из профиля и показывается без редактирования. Если в профиле ID нет, отправка запрещена, даже при переданном вручную ID или телефоне. Есть переход в профиль. Сервер каждый раз заново читает профиль из БД, отклоняет подмену получателя; проверка действует и для повторной отправки связанной заявки.

[PR #26](https://github.com/tonimasite-dotcom/gpm_platform/pull/26) слит и установлен. Код: 6e29d7d43222b5cd089d517d6ba55ef456aa74fe; merge: a39a23411884cd7d8f7462d9e60ac1449aa50bdd. Миграций и автоматического заполнения профилей не было. Поле профиля, ранее выпущенное в PR #25, сохранено; обязательность проверяется при отправке.

CI, серверные проверки обходов и существующей публикации, проверки профиля и UI пройдены. Offline-сборка и сравнение графа подтвердили изменение только двух frontend-модулей при неизменном CSS и составе остальных модулей. Свежая закрытая резервная копия, пакет, пробная установка/откат и архив проверены; полного восстановления БД не выполняли. После установки совпали хеши рабочих файлов и HTTPS assets, новая страница отдает новую сборку. Установленный код проверен с пустым профилем и подставленным ID/телефоном: отказ до исходящих запросов. Учетные данные, роли, сохраненные ID, история миграций, настройки и cron сохранены. Квитанции и служебные подробности остаются закрытыми.

Остается визуальная приемка владельца: обновить TS через Ctrl+F5, сохранить ID в своем профиле и проверить окно отправки. Реальные заявки этим проверочным этапом не публиковались. Регистрация в CRM не создает аккаунт GPM; выдача корпоративных ID в приложении и прежняя выдача #1 не повторялись. Сторонним логистам приложения ID и карточка не выдаются.

Основная CRM и GPM этим выпуском не менялись. Основную CRM не менять без отдельного явного согласования.
