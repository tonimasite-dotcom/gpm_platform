# GPM: проект бригадных отметок

После СТАРТ владельца изучены текущие QR-отметки GPM и исходники тестовой CRM.
Рабочие данные и код CRM не менялись.

Владелец выбрал: старший сканирует QR каждого исполнителя; клиент подтверждает
собранный список через QR старшего. Нужны время и геолокация. При проблемной
геолокации отметка ожидает ручного решения владеющего заказом логиста.
Подтвержденный табель нужен в GPM и в CRM. Для одного исполнителя старший не нужен.

Подготовлен [проект](plans/crew-attendance/PLAN.md), точный проект трех новых
таблиц GPM и проверки ограничений схемы на одноразовой БД Actions.
Это проект для согласования объема, а не реализованная функция.
SQL не подключен к init_db и не применяется к рабочей БД.

Перед реализацией/рабочей миграцией отдельно согласовать три новые таблицы
по AGENTS.md. Затем реализовать геолокацию, сбор, подтверждение, ручную проверку,
явную связь рабочих и отдельный контракт обмена табелем TS/GPM; пройти тесты
и приемку на реальных устройствах. Подробные параметры, риски и откат в плане.

Основную CRM не менять без отдельного согласования; разрешенная сверка только
для чтения. Очистка заявок не разрешает удалять схемы, аккаунты, auth, аудит,
настройки, backup и инфраструктуру. debt-off, деловую почту, scheduler и очереди
TS не включать. GPM и CRM/TS строго разделять. Исходники и проверки через GitHub
и Actions, без новых локальных копий на C:. Закрытые сведения в Git не добавлять.
