- Сессия началась с проверки чек-листа из хендоффа 16.09 и наткнулась на

- По итогам пользователь попросил не просто починить баг, а сделать новую
  схему нумерации: каждый клиент/логист получает постоянный код при
  регистрации (`L1`, `L2`… / `C1`, `C2`…, по порядку регистрации), и его
  заказы нумеруются `{код}-{ДДММГГ}-{n}`, где `n` — счётчик заказов этого
  актора за день (сброс на 1 каждый день по Europe/Moscow). Пример:
  `L1-180926-1`.
- Реализовано, протестировано (58 backend + 36 Flutter тестов зелёные,
  `flutter analyze` чисто) и задеплоено на продакшен
  (`gh workflow run deploy-production.yml -f target=backend`). Сервер
  теперь **всегда** сам генерирует номер для аутентифицированного клиента/
  логиста и игнорирует то, что прислал клиент — это же закрывает
  первоначальный баг. Бэкфилл существующих аккаунтов встроен в
  `deploy-production.yml` (шаг `app/backfill_actor_codes.py`), выполнился
  при деплое: назначил коды 1 клиенту и 2 логистам, которые
  зарегистрировались раньше и кода ещё не имели.
- Подробности реализации, найденный попутный баг (рассинхрон полей `id`/
  `external_order_id`) и почему часовой пояс сделан через фиксированное
  смещение, а не `zoneinfo` — раздел 4.2 хендоффа.
- **У ассистента нет прямого SSH к продовым серверам** — только у GitHub
  Actions (секрет `PROD_SSH_PRIVATE_KEY`). Любые новые разовые
  серверные операции — через шаг в `deploy-production.yml`, не через
  попытки подключиться напрямую.
