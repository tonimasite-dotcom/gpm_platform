# Подготовка общей базы CRM — WIP, пауза владельца

Только частная подготовка для ts.workstaffcrm.ru. Работающие CRM этим пакетом
не обновлены. Ветка `work/ts-baseline-2026-11-06`. Скрипты не являются готовым
установщиком и не имеют проверенного live apply/rollback.

Частный каталог на CRM-сервере: `/root/gpm-ts-update/20261106-baseline-01`.
PHP и frontend-сборка кандидата пройдены, 11+16+35 автономных сценариев GPM прошли.
Зашифрованная копия ts проверена: SQL восстановлен в отдельный MySQL; все строки
72 таблиц совпали с дампом. Все 24862 записи файлового архива проверены по
метаданным/SHA. Полная файловая распаковка не проводилась; внешняя ссылка на
хранилище test.workstaffcrm.ru не обходилась и не копировалась.

**Репетиция миграций не принята**: итог `ORIGINAL_TABLE_DATA_CHANGED` после
AddReferencePermissionsForGpmTs. В частной БД теперь 112 таблиц / 217 строк
истории миграций. До разбора нельзя считать миграции успешными и применять их
к ts. Данные карт и освобождение email/reset-записей отложены. Частный MySQL
по просьбе владельца выключен, все его файлы сохранены.

Назначение файлов:

- prepare.py — новый частный каталог, allowlist источников и первичная трехсторонняя сверка;
- merge_candidate.py — актуальный общий код с явными ts/GPM-вставками и настройками;
- check_candidate.py — копии зависимостей, lint, автономные тесты, сборка без сети;
- backup_ts.py — потоковый encrypted backup ts без plaintext-дампа/архива;
- init_rehearsal.py — создание НОВОГО частного MySQL, отказывается от существующего каталога;
- restore_receiver.py / restore_from_windows.py — восстановление только в пустую частную БД;
- correct_manifest.py — исправление счетчиков INSERT с явным списком колонок;
- verify_files_windows.py — проверка каждого члена файлового архива без распаковки;
- adapt_rehearsal.py / payload — адаптации строго для репетиции, живые CRM отклоняются;
- run_rehearsal_snapshot.py — сохраненный снимок фактического запуска, включая PHP payload.

При продолжении использовать сохраненную БД и рабочую папку. Не запускать
init повторно, не сбрасывать таблицы. Не запускать merge_candidate повторно
после адаптации без разбора: он заменит адаптированные файлы общими исходниками.
Не запускать обычные migrate/seed/rollback, сквозную публикацию или sync ради проверки.
Сначала прочитать новый handoff паузы и проверить фактическое состояние.

Границы: основная только читается; обе работающие CRM не менялись. Новые правила
синхронизации — отдельная задача. Аккаунты, авторизация, аудит, конфигурация,
секреты, резервные копии и инфраструктура не удаляются ради обновления или отката.
Полные исходники CRM, реальные настройки, ключи, рабочие записи и plaintext backup
в этот каталог Git не включены. Сырые диагностические логи остаются root-private.
