# Частная репетиция ts 09.11.2026

Это журнал исполненных инструментов, не установщик для работающей CRM.
Все изменяющие скрипты привязаны к новым private-путям. Повторный запуск
большинства шагов намеренно отвергается; не удалять guards/артефакты ради повтора.
Основную CRM не менять. Новые правила синхронизации сюда не входят.

Последовательность и ошибки:

1. prepare_switch.py создал две новые файловые версии и отдельные MySQL.
   Исходные recovery/candidate не заменялись. После ошибки Python 3.7 копирование
   продолжено до запуска БД; файлы и кандидатные хеши сверены.
2. adapt_switch.py добавил явный private-контекст старой/новой версии и guard
   PlanningDayBoundary. Old smoke отдельно фиксирует прежнюю ошибку истории ставки.
3. build_check_tools.py сформировал проверки из неизмененных baseline/checker.
4. run_switch.py: отказ после 3 миграций, проверенный возврат; затем timeout DDL.
   continue_after_timeout.py сохранил offline-копию, но продолжение выявило
   поврежденную InnoDB-копию. Ее не ремонтировали вручную и не использовали дальше.
5. prepare_fresh_upgrade_database.py сохранил неудачную БД, создал новую и восстановил
   данные. Только ее buffer pool увеличен до 512 MiB. run_fresh_switch.py завершил
   37 миграций; wrapper ошибочно отверг сопутствующие строки консоли.
6. run_final_full.py сохранил первый успешный new-slot и создал новый final-slot/DB.
   37 миграций прошли, но обнаружилась ошибочная привязка проверочного root.
   fix_check_root.py сохранил прежние скрипты и исправил только root; guards остались.
7. check_final_state_and_email.py подтвердил сохранность данных и воспроизвел
   чужой почтовый код при правильном пароле. fix_email_code_binding.py изменил
   только частные LoginController: exists ограничен email входящего пользователя.
   Настройка подтверждения почты не менялась. Исходный код сохранен, новый manifest
   создан отдельно. merge_candidate.py содержит ту же поправку для будущей сборки;
   повторять merge/adapt над сохраненным кандидатом нельзя.
8. resume_final_acceptance.py повторил 8 email, 42 forms, 40 functional, smoke,
   negative-context, независимую сверку данных; затем атомарно вернул old-slot.
   Файловые байты/режимы/владельцы, старая DB и new activation-state проверены.
9. stop_switch_mysql.py штатно выключил только две новые private MySQL.
   export_safe_report.py экспортирует отобранные JSON без env, SQL и raw errors.

read_ts_metadata.py читает только метаданные работающей ts без Laravel/DB.
FPM найден по сокету через /proc: /opt/php74, общий master на 3 пула. Перезапусков
не было. Проверка смены кода через FPM/opcache еще не выполнена.

Полный цикл доказан частями с продолжением после ошибок инструментов.
Единого непрерывного успешного прогона и замера производственного простоя нет.
Не складывать отдельные замеры и не выдавать их за обещанное окно.
Не запускать общий scheduler, sync/publish, migrate:rollback или DROP.
Все неудачные DB/деревья/снимки сохранены, свободно около 2 GB: новые полные
копии без проверки места не создавать. Порядок хранения/освобождения не согласован.
