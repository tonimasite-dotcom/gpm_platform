# TS demo-06: блокировка отправок с обычным email-входом

Владелец оставил текущий вход по коду на email. Контроллер входа, JWT, пароль,
captcha, проверка кода, auth-конфигурация и роли не меняются. Локальный inbox
не устанавливается. Общая почта остается заблокированной, исключение получает
только существующий sendVerifyMessage: исходный шаблон и адрес пользователя,
те же SMTP-параметры филиала, отдельный экземпляр Laravel Mailer/Swift.
Он не регистрируется в контейнере или Mail facade и не меняет глобальный mailer.
Нет разрешения по теме письма, внешнему HTTP-флагу или настройке окружения.

Новый пакет собирается prepare_email.py только в новом demo-06 из проверенного
demo-05 и текущих before SHA. 25 файлов: 23 существующих и два новых helper.
Четыре действующих запрета дебиторки сохранены. Блокировка остальных внешних
каналов и сохранение GPM совпадают с предыдущим пакетом; основные данные,
env, cron, маршруты, Kernel, схема и учетные записи не заменяются.

Серверные артефакты: /root/gpm-ts-update/20261110-demo-06,
инструменты: /root/gpm-ts-update/demo-email-tools-20261110.

Проверки: 79 transport/email (реальный PHP/Swift и искусственный SMTP внутри
отдельной network namespace), 29 install/failure/resume, PHP 7.4 lint всех
25 целей и четырех helper, Python AST, свежий read-only preflight.
Репетиция не запускает SQL, живой sync, задания CRM или настоящие отправки.
Первые отказы SMTP-теста были в фикстуре: невалидный искусственный адрес и
проверка MIME без декодирования. Исправлены; это не изменения рабочего входа.
Старые 14 auth-тестов исправленного LoginController к этому пакету не относятся
и не считаются его результатом. GPM-результаты переиспользованы по точным SHA.

ключ отдельно. Это не новая полная SQL/files-копия; миграций/правок строк нет.

atomic swaps с сохранением uid/gid/mode, invalidation только 25 файлов через
