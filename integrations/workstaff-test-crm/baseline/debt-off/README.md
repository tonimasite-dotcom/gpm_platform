# Отдельное отключение дебиторки TS, 10.11.2026

Прямое поручение владельца: отключить фоновую проверку дебиторки и email должникам
на ts.workstaffcrm.ru. Это отдельный узкий выпуск без ожидающего согласования
пакета авторизации/деморежима из 27 файлов.

В текущей TS найдены `debit:check_debit` (проверка оплат и письма) и
`command:checkCustomerDebit` (пересчет дебиторки). Отдельного `debit:notify` нет.
Меняются только CheckDebit.php, CheckCustomerDebit.php, WebKlexMailClient.php:
возврат до тела двух команд, private sendMail и sendDebitMessage. Guard нельзя
снять флагом cron/env: для TS достаточно фактического base_path или ее app.url.
Вызов не обращается к БД и почте. Основной код метода сохраняется за guard.

Общий Kernel/cron, расчеты UI/учетные строки/суммы, GPM sync, auth, обычные письма
входа, APP_KEY и SMTP-настройки не меняются. Основная CRM не читается/не меняется.

Серверный каталог `/root/gpm-ts-update/20261110-debt-off-01`, инструменты
`/root/gpm-ts-update/debt-off-tools-20261110`. prepare.py одноразовый, только новый
каталог. FastCGI helper fpm_probe.py копируется без изменений из соседнего demo,
engine install импортируется из прежнего проверенного demo-tools; полный 27-file
apply не вызывается. Без --apply release.py только проверяет before/after SHA,
свежесть/покрытие backup и отсутствие старых TS debt/queue/scheduler процессов.

Частная приемка вызывает четыре настоящих защищенных метода в namespace без
сети, с traps на DB/mail/filesystem; исходное тело не достигается. Отказы установки
отрабатываются на четырех границах с сохранением maintenance и точным resume.
При live apply меняются три файла атомарно под кратким TS-only maintenance;
инвалидируются только они через отдельный TS FPM socket, повторяются реальные
вызовы handlers в чистом container без Laravel bootstrap/DB/mail, проверяются
401 /api/user и 200 главной. Общих reload/reset нет.

Свежий encrypted backup затрагиваемых исходников уже входит в проверенный
code backup demo-04: SHA 4d1555014fd01a636d21444076a5aabdfc95236ad7e2cee17e3198c0d621cc01.
Он расшифрован/восстановлен с совпадением всех SHA; перед apply снова сверяется
покрытие текущих файлов и давность меньше суток. Backup не содержит БД,
поскольку в выпуске нет SQL/migration/seed/операций с рабочими строками.

После отдельного отключения три before SHA полного пакета c350b699... устареют.
Старый пакет не применять вслепую: нужен rebase/checkpoint на новые SHA, с
сохранением постоянного запрета дебиторки/писем. Изменение auth остается на
отдельном согласовании; одобрение отключения дебиторки его не заменяет.
