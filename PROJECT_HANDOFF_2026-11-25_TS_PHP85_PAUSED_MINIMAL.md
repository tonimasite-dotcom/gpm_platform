# TS: минимальная точка остановки 25.11.2026

Владелец попросил аккуратно остановиться для перехода на другой компьютер.
До явного продолжения выполнять только сохранение контекста. Не запускать
сервисы кандидата, проверки, перенос данных или переключение домена.

Задача: полностью перенести TS на сервер текущей основной CRM и сразу
подготовить TS под PHP 8.5 / MySQL 8.4. Это прямое разрешение на отдельное
окружение TS на новом сервере. Основная CRM остается только для чтения.

## Где остановились

- Старая TS работает на прежнем месте. Ее данные, код и отдельный обмен
  не менялись, домен не переключен. Основная CRM отвечает, ее прежние
  настройки совпали по хешам; ее PHP/MySQL не перезапускались.
- Закрытый кандидат TS подготовлен на PHP 8.5 / Laravel 13 и отдельной
  MySQL 8.4. Первичный снимок прошел через временную MySQL 8.0.
  Все 72 таблицы совпали по содержимому, в том числе после синтетических проверок.
- Изменения совместимости сохранены отдельно с исходными версиями и хешами.
  Сохранены ключи приложения/JWT, аккаунты, ID, настройки и данные TS.
  В кандидате добавлены только два nullable-поля журнала: event и batch_uuid.
  Общие миграции не запускались.
- Проверены 502 PHP-файла, загрузка 449 классов, 549 маршрутов,
  23 синтетических сценария, 42 сравнения прежних вычислений дат.
  Вход с email-кодом, JWT/роли, ставки/история, фото, XLSX/PDF/DOCX,
  блокировка деловой почты и пробный обмен GPM прошли.
  Это не заменяет ручную приемку всех экранов и QR на телефонах.
- По отдельному согласию владельца сверены только два GET API реального логиста:
  /api/user и /api/logist_orders. Обе копии дали HTTP 200 и одинаковый JSON.
  Временный JWT не выводился и не сохранялся. Часовой пояс отдельной
  MySQL TS приведен к прежнему московскому +03:00; основную БД не меняли.
- HTTPS кандидата проверен. При остановке его отдельный PHP и обе
  подготовительные БД чисто выключены, временный vhost сохранен вне активных
  настроек. Новые задания обмена не установлены; flags кандидата выключены.
  Общий nginx перечитан после проверки только ради TS; прежние настройки основной сохранены.

Файлы, SQL и небольшие пакеты совместимости/остановки сохранены и проверены
в зашифрованном виде в частном окружении переноса. Частные пути, receipts,
список изменений и точный порядок возобновления находятся в RECOVERY.json,
state.json и pause-receipt.json в закрытом каталоге переноса на целевом сервере.
Найти и прочитать их до действий; не повторять неидемпотентные шаги вслепую.
Полные TS/CRM, БД, частные отчеты и секреты в этот Git-снапшот не входят.

## Следующий шаг после продолжения

1. Восстановить доступ с другого компьютера со строгой проверкой SSH-ключа.
   Прочитать частное состояние. Сервисы кандидата сейчас выключены намеренно.
2. Помочь владельцу сохранить ключ расшифровки на другом компьютере.
   Ключ пока только на целевом сервере; внешняя копия не создана.
   На старый сервер ключ НЕ копировать: владелец планирует его удалить.
   Перед удалением источника нужна также независимая копия зашифрованных архивов.
   Пароли/ключи не выводить в чат или Git. Старый сервер сейчас не удалять.
3. После согласования конкретного переключения возобновить кандидат,
   сверить свежесть исходного кода и подготовить окончательные файлы/снимок БД.
   Нынешний снимок предварительный: старая TS продолжает принимать изменения.
   Сохранить поддержанный путь БД через 8.0, две добавочные колонки и +03:00.
4. Провести финальную TS-only приемку, затем короткую остановку записи/обмена,
   окончательный перенос и переключение. Владелец имеет доступ к DNS FastVPS
   и изменит запись по инструкции; пока ему сказано ничего не менять.
   Две копии обмена одновременно не запускать.
5. Довести отдельное продление сертификата TS и резервное копирование.
   Исходник и backup не удалять. После новых записей на целевом сервере
   возврат требует сверки данных, а не простого переключения домена назад.

Дебиторка, деловая почта, общий scheduler и фоновые очереди выключены;
обычные email-коды сохранить. Основную CRM/ее службы не менять.
Очистка не разрешает удалять схему, аккаунты, авторизацию/JWT, аудит,
настройки, backup или инфраструктуру. Посторонние исправления не добавлять.
Полную TS на серверы GPM не помещать, копии проекта на C: не создавать.

GPM не выпускался заново: прежняя версия и ручная приемка описаны в
