## Все 12 замечаний

| № | Замечание | Состояние в доступном коде |

| 1 | Запрет рабочего менять гражданство; права логиста и рекрутера | Не закрыто. Рабочий может менять гражданство и через UI, и через API собственного профиля. Нужный редактор чужого профиля не найден. В активном API предусмотрены только роли `client`, `worker`, `logist`; роли рекрутера и администратора отсутствуют. |
| 2 | Не отправляется заказ из тестовой CRM | Текущее исправление не подтверждено. Ранее интеграция работала, что зафиксировано в handoff от 01.09. Публичный health GPM исправен, но это не проверка отправки из CRM. Нужны текущие нормализованные status/detail из publisher/log тестовой CRM. |
| 3 | Удалить категорию рабочих | Не закрыто. Поле «Категория рабочих» есть в общей форме создания, которую открывает и логист; значение отправляется серверу. |
| 4 | Ввод ставки в час при создании заказа | Частично существовало раньше, требование не закрыто. Ставки поддерживаются backend и редактором черновика, но общая форма создания предлагает только предполагаемый бюджет. |

PNG имеет размер 1500×1702, UI показывает его в 48×48. Одна величина разрешения не доказывает хорошее качество: требуется проверить исходник и отображение. |
| 6 | Показывать ставку и предполагаемый заработок в списке и деталях рабочего | Частично. Детали показывают поля ставок при режиме `rate`; список не показывает оплату, предполагаемый заработок из бюджета в деталях также отсутствует. |

Редактирование этих полей опубликованного заказа через PATCH отклоняется. Это прежнее поведение, закреплённое кодом, документацией и тестами. |
| 8 | В профиле РФ, у логиста при отклике «Не РФ» | Не закрыто. Backend сохраняет отклик без вложенного актуального профиля рабочего. UI логиста читает `application['worker']`, при его отсутствии получает пустой объект и выводит «Не РФ». `getWorkerProfile` также читает локальные demo-данные, а не профиль другого пользователя из API. Это найденная причина неверной метки; конкретный аккаунт тестировщика не проверялся. |
| 9 | «Паспорт не подтвержден / подтвержден» | Не закрыто. В отклике остались «Паспорт нет» / «Паспорт OK». Признак берётся из наличия строки `passport`, а не из статуса проверки документа. |
| 10 | Тип занятости «Подрядчик» и управление им | Частично изменено 02.10 и задеплоено. `e363230` убрал тип занятости из собственного профиля рабочего. Backend-поле и метка в карточке отклика логиста сохранены, поэтому замечание целиком не закрыто. |
| 11 | Завершение и оплачиваемые часы только по приходу/уходу | Частично. QR-табель реализован и задеплоен 01.10 (`71db271`). Рабочий всё ещё отправляет `DONE_PENDING` отдельной кнопкой; API проверяет назначение и статус, но не наличие прихода/ухода. Начисление использует `hours` и `min_time` заказа, а не длительность табеля. |
| 12 | Оценка «Справился» не меняет рейтинг | Не закрыто. В API-режиме `completeOrderWithResult` отправляет только статус `CONVERTED`, выбранная оценка не отправляется. Изменение рейтинга реализовано только в локальной demo-ветке. |

## Как восстановить именно работу 12.10

Нужны файлы, Git-история или текст сессии с другого компьютера. Там сначала
проверить `git status --short`, `git branch -vv`, `git log --all` и `git reflog`,
включая отдельные worktree. Сохранить незакоммиченные изменения до любого
обновления checkout. Затем сравнить найденные правки с этой сводкой и только
после этого определять, что осталось реализовать и подготовить к deployment.

Отдельно проверить тестовую CRM: её PHP/Vue publisher находится на другом
сервере и не входит в этот репозиторий Flutter/FastAPI. Вчерашние изменения
CRM могли остаться только там. Основная CRM не проверялась и не изменялась.
