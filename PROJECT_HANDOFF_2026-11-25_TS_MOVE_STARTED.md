# TS: перенос и переход на PHP 8.5 / MySQL 8.4

25.11.2026 владелец поручил полностью перенести TS на сервер текущей
основной CRM, подтвердил начало и затем прямо расширил объем:
сразу подготовить TS под PHP 8.5 и MySQL 8.4 для проверки будущей связки с основной.

Это разрешает отдельное окружение TS на новом сервере. Прежний запрет
записей на новом сервере заменен только для этой задачи.
Основная CRM остается только для чтения: ее код, данные, настройки
и службы не обновлять, не перезапускать и не использовать как базу TS.

## Текущее состояние

- SSH-отпечаток подтвержден владельцем через Moba, строгая проверка ключа сохранена.
- Проверены ресурсы и изоляция; перенос ограничен по скорости и ресурсам.
- Первичная копия файлов и согласованный снимок 72 таблиц TS переданы потоково.
  Зашифрованные резервные копии проверены расшифровкой, SHA и проверкой сжатия.
  Это предварительный снимок: перед переключением нужны свежая база и изменения файлов.
- Копия TS закрыта от публичного доступа. Ее отдельный обмен с GPM выключен.
- Снимок базы восстановлен на временной изолированной MySQL 8.0.
  Отдельная MySQL 8.4 запущена без TCP и с выключенными событиями;
  перенос данных 8.0 -> 8.4 еще идет, приемка данных не закончена.
- Кандидат TS запускает Laravel на PHP 8.5; зависимости подобраны по совместимой
  версии основной CRM. Рабочий код TS сохранен, полная основная CRM не копировалась.
  Адаптируются даты, middleware, журнал изменений и почта. Общая приемка не пройдена.
- Все изменения пока относятся к закрытой целевой копии TS.
  Старая TS продолжает работать. Домен не переключен, исходные файлы и данные сохранены.
  Контрольные хеши настроек основной CRM совпадают, ее службы не перезапускались.

Полные копии CRM, SQL, частные отчеты и ключи находятся только в частном
окружении переноса. В публичный Git их не добавлять.
Ключ шифрования хранить отдельно от архива; его независимое хранение еще проверить.
Подробные пути и результаты проверок искать в частном состоянии переноса,
не восстанавливать их из догадок и не публиковать в Git.
Не запускать повторно неидемпотентные шаги без проверки текущего состояния.

## Дальше

1. Завершить восстановление в отдельную MySQL 8.4, сравнить все таблицы,
   строки, ключи, связи, аудит и настройки. Не запускать все миграции автоматически.
2. Завершить совместимость PHP 8.5 / Laravel и зависимостей.
   Проверить вход/JWT/роли, отдельные email-коды, файлы/фото,
   заявки/расчеты/ставки, TS/GPM, версии модерации и назначение старшего.
   Синтетические проверки выполнять в закрытом окружении без внешних отправок.
3. Проверить debt-off и блокировку деловой почты при новом пути TS и новых библиотеках.
   Обычный email-вход сохранить; ключи приложения/JWT, аккаунты и ID не сбрасывать.
4. Подготовить отдельный PHP-FPM/vhost/TLS TS, ограниченный доступ для проверки,
   точный порядок остановки записи, финального переноса, проверки и возврата.
5. Только после приемки переключить TS: остановить запись/ее отдельный обмен,
   перенести свежую базу/файлы, проверить, переключить домен и включить один обмен.
   Две копии обмена одновременно не запускать.
6. Старую TS и резервные копии не удалять. После новых записей на целевом сервере
   возврат требует сверки данных, а не простого переключения домена назад.

Не обещать отсутствие замедлений основной CRM. Ограничения ресурсов и контроль
ответов основной сохранять на тяжелых этапах.

## Обязательные границы

Только TS и необходимые зависимости для перехода на согласованные версии.
Основная CRM без изменений; серверы GPM и CRM не смешивать, полную TS на GPM не размещать.
Номера CRM не переформатировать, ID логистов не переназначать.
Дебиторку, деловые рассылки, общий scheduler и фоновые очереди не включать.
Очистка не разрешает удалять схему, аккаунты, JWT/авторизацию, аудит, настройки,
backup или инфраструктуру. Изменения жизненно важных компонентов разбирать
по объектам и последствиям, не включать посторонние исправления автоматически.
Копии проекта на C: не создавать; секреты, БД и полные CRM в Git не добавлять.

GPM остается на ранее выпущенной версии из
PROJECT_HANDOFF_2026-11-24_SESSION_MINIMAL.md.
Ручная приемка QR на телефонах и новых логистов еще не завершена.
