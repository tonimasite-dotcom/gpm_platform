## Найденные и исправленные ошибки кандидата

1. LoginController передавал request->filled('remember') вторым аргументом
   JWTGuard::attempt(). В JWT этот аргумент означает «выполнить login», а не
   «запомнить меня». Без поля remember пароль проверялся, но пользователь не
   устанавливался; последующее обращение к user->active давало ошибку.
   Теперь JWTGuard вызывается с обычным выполнением входа. Для иных guard
   прежняя семантика remember сохранена. Проверки пароля/active/profile остаются.
   Проверены remember отсутствует, false и true, неверный пароль и inactive.
   Живая авторизация не менялась. Это отдельный конкретный эффект изменения
   авторизации кандидата; явно включить его в состав перед реальным применением.

2. GpmWorkerRateController передавал только workers_cost/work_type_id в новый
   HistoryOrderService, который ожидает полный снимок и читает status/payment
   и другие поля. Приемка воспроизвела ошибку. Теперь передается полный текущий
   снимок с одной замененной ставкой. Общий сервис намеренно не пишет ставки
   при закрытии заказа; редактор GPM передает customTranslate только для своего
   отдельного действия «Ставка рабочего». Общие правила истории не менялись.
   Проверены запись ровно одного изменения, отсутствие дублирования при повторе
   и отсутствие изменения адреса/клиентских сумм. Собственная PHP-заготовка
   worker-rate/GpmWorkerRateController.php в репозитории также исправлена.

Остальные первоначальные остановки были недостатками синтетического сценария:
обязательный contact_person_id, имя поля login, справочный payment_type_id и
преобразование ModelNotFoundException в HTTP 404. Для них приложение не меняли.
