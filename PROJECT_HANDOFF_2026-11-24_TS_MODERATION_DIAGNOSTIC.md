# Диагностика получения заявок TS логистом GPM

24.11.2026 владелец сообщил: после успешной отправки из TS не видит
заявку в приложении. Он отдельно подтвердил: работает только с TS;
основную CRM не менять и ничего в нее не переносить до завершения тестов.

## Проверка и правила

Добавлен .github/workflows/inspect-gpm-order-readonly.yml:
ручной запуск только из main в production, фиксированный backend GPM,
проверенный SSH host key и проверка принадлежности каталога.
Запрос передается через закрытый временный selector, без номера заявки
в коде и публичном выводе. Чтение PostgreSQL принудительно read-only,
с ограничением времени запросов, без init_db, миграций, выдачи аккаунтов,
создания записей или повторной отправки. Python bytecode не записывается.
Вывод ограничен обезличенными признаками приема, назначения, видимости
и наличия перехода статуса в аудите. ФИО, телефоны, адреса, UUID аккаунтов,
исходные JSON и содержимое сообщений не выводятся.

Read-only runs 45356246492 и 45356679102 success.
Код диагностики: e3cc8f6fa4c71fa50b3c8926eda4ab5986256599,
781a47970fc3ab7d0e567e1d7d028683e743002d.
Временный закрытый selector после проверки удален; существующие секреты
доступа сохранены. Новые запуски требуют нового закрытого запроса.
Подробности конкретной заявки переданы владельцу в чате, в Git их нет.

Новая публикация из TS получает NEW и должна приходить на модерацию.
Повторная отправка уже связанной заявки выполняет синхронизацию существующей,
сохраняя ее состояние. Она не создает дубль и не сбрасывает ранее выданное
одобрение. PROCESSED в интерфейсе логиста — «Одобрен», NEW — «На модерации».
У логиста в актуальном интерфейсе по умолчанию «Все», фильтр дат публикации
не задан. «Сегодня» — не объяснение отсутствия входящей модерации у логиста.
Сброс одобрения или истории ради повторного теста автоматически не выполнять.

## Продолжение

Владелец проверяет раздел «Все» или «Одобрен» и обновляет список.
Если карточки нет даже там, продолжить с фактическими фильтрами/кабинетом,
не отправлять заявку повторно и не менять ее статус без разбора.
Ручная видимость карточки в браузере владельца еще не подтверждена.

Прямой SSH с этого компьютера не использовался: для backend нет локально
проверенного host key. Обход проверки запрещен. Штатный доступ Actions
проверен и работает; не считать отсутствие локального ключа блокером.

Код приложения frontend/backend в этой диагностике не выпускался:
backend остается a53ab626, последняя веб-версия 5232fe2b.
Новые backup для чтения данных не требовались.
Основная CRM не читалась и не менялась; TS, его cron, почта и данные
не менялись. Аккаунты, JWT/вход, схема, аудит, состояния заявок и настройки
рабочего приложения сохранены. Рабочие данные и служебные локаторы копий
в Git не добавлены. Изменены только диагностический workflow и контекст.
