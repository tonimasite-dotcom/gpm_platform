Старый checker и исходный снимок не перезаписывались. Подробности — в handoff
TS_DATA_AND_RECOVERY от 9 ноября. Старые подтверждения не являются новой
приемкой актуального Laravel 13/PHP 8.5.

По отчету 13 ноября test удален, TS storage независим; удаление не повторялось.
Частный PHP 8.5.12 сохранен на старом сервере. Его пересборка/инициализация БД
не выполнялась. Найдены сохраненные результаты работ, еще не вошедшие в прежний
handoff: перенос 13 951 очищенного файла, Composer platform PASS, lint 820 PHP,
synthetic kernel bootstrap, разрешение зависимостей двух контроллеров,
публикация через Laravel HTTP fake и пять сценариев синхронизации с MySQL.
Эти прежние тесты в текущем этапе не запускались заново.

## Проверка редактора ставки

Использована существующая частная синтетическая база: структура 72 таблиц TS
и ранее добавленная отдельная таблица зависимости финансового guard.
Рабочие строки TS или основной не копировались. Полные миграции не запускались,
история миграций не подменялась. MySQL 5.7.42 запускался только для теста,
с отдельным datadir/socket, без TCP и в отдельном network namespace.
PHP работал в отдельном chroot и network namespace, HTTP запрещен/fake.

Первая тестовая запись требовала заполненного типа оплаты; fixture исправлена.
После этого воспроизведен реальный дефект адаптации: новый HistoryOrderService
ожидает полный снимок, а GpmWorkerRateController передавал только два поля.
Результат — Undefined array key status_id до сохранения ставки.

В частном контроллере добавлена передача полного снимка текущего заказа
с новой ставкой и явной подписью workers_cost для истории. Старый файл сохранен.
Права, область видимости, авторизация/JWT, общий сервис истории не менялись.
Контрольный SHA исправленного контроллера:
`5f2fff42688da13c3173fce6e43a212f9e6254b94ba70ce8cc882760530efe83`.
Это адаптация только частного кандидата; штатные установщики и live TS не изменены.

14 сценариев PASS: успешная ставка с сохранением прочих полей; старое/новое
значение в истории; повтор запроса без второй записи истории; устаревшая ставка;
постороннее поле; некорректная ставка; закрытые статусы 3/4/5; чужой владелец;
чужой город; отсутствие права чтения; запрет основной идентичности;
модельная защита адреса от логиста.

Контроллер вызывался напрямую с синтетическим actor, часть проверок его прав
подменена fixture. Это не приемка настоящих учетных записей, JWT/middleware,
браузерной формы или реальной синхронизации GPM. Реальных HTTP-запросов,
рабочих заявок, писем и внешних операций не было.

После каждого запуска сравнивались строки всех 73 таблиц до/после rollback:
полное совпадение. Это не восстановление auto_increment и не доказательство
отката рабочих финансовых данных. Частный MySQL штатно выключен, socket/PID
отсутствуют. Все failed runs сохранены отдельно, не перезаписаны.
Проверка переносимого скрипта выявила несовместимость Path.is_relative_to

контрольный SHA проверены на сервере, 14 сценариев PASS.

## Следующий шаг и границы

Продолжить частную адаптацию demo/debt-off и обычных email-кодов к актуальному
Laravel, затем frontend редактора ставки и проверку через настоящие маршруты,
middleware/JWT с синтетическими учетками. Не выдавать direct controller tests
за сквозную приемку. AuthServiceProvider и другие жизненно важные компоненты
не менять без конкретного плана последствий/восстановления и согласования.

Сохраненный статический аудит показывает 38 непримененных миграций, у семи
найдены маркеры изменений/записи данных. Это ориентир, не полный анализ риска.
Перед runtime на данных TS нужны разбор необходимой схемы и транзитивных
зависимостей, свежий проверенный backup TS, репетиция сохранности и полного
отката. Финансовый откат к старому коду по-прежнему не доказан.
До этого готовность к live/первому сквозному тесту не заявлять.

Все работы и private checks ТОЛЬКО на старом сервере. Новый сервер и основная
ТОЛЬКО читать; не создавать там файлы/backup/БД, не запускать CRM/задания,
не менять службы/DNS и не переносить туда TS. Прежние закрытые каталоги оставить.
Рабочая TS этим этапом не менялась. Изменение частного контроллера не является
выпуском; нового production deployment нет. CI для этого checkpoint не запускался.

Сохранить GPM, ставки, ограничения логиста, настройки/учетки/данные TS, debt-off,
демозащиту и обычные коды входа на email. Общий scheduler, рассылки, реальные
внешние операции и live sync как smoke не запускать. Ответы коллег по sync
уже есть, новые правила обмена отдельны. Очистка заявок не разрешает удаление
схемы/учеток/auth/аудита/настроек/секретов/backup/общей инфраструктуры.
