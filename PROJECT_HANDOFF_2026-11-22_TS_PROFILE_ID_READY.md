# GPM: ручное поле ID в профиле TS подготовлено — 22.11.2026

[Черновой PR #25](https://github.com/tonimasite-dotcom/gpm_platform/pull/25) подготовлен, не слит. Поле профиля TS еще не опубликовано; рабочие файлы и схема этим этапом не менялись. Прежний выпуск ID и отправка по ID продолжают работать.

Согласованная логика: логист Джи Пи Эм регистрируется в приложении по доверенному корпоративному приглашению и получает постоянный ID. У стороннего логиста приложения ID и карточки ID нет. Регистрация в CRM не создает аккаунт GPM.

В TS подготовлено ручное поле «ID в приложении» в своем профиле и карточке пользователя для ролей «Логист» и «Администратор». Значение проверяется и подставляется в окно отправки. Его можно очистить. Права проверяются сервером; пароли, телефоны, роли и вход сохраняются. Существующие профили автоматически не заполняются.

Проверки кода, ролей, online-миграции на изолированном MySQL и offline-сборки пройдены. Модульный состав и CSS сохранены, изменены только три нужные формы. Закрытый пакет, проверенный откат и read-only план установки готовы. Backup и подробные квитанции сохранены в закрытом контексте; служебные локаторы, архивы, данные и секреты сюда не включены.

Следующий шаг — отдельно согласовать добавление одного необязательного поля TS и выпуск по AGENTS.md. До этого миграцию и установку не выполнять. После одобрения заново сверить backup и live-хеши, применить только выбранную миграцию и точечный пакет. Общий набор миграций не запускать. Откат кода сохраняет колонку и введенные ID.

Основная CRM и GPM этим этапом не менялись. Не удалять аккаунты, auth, схемы, аудит, backup или инфраструктуру. Дебиторку, деловую почту, scheduler и очереди TS не включать; обычные email-коды и отдельный обмен GPM сохранить. Общую модернизацию TS не возобновлять. Работать через GitHub/Actions и разрешенные серверы, без локальных исходников, SDK, сборок и архивов. Приемка ролей/анкеты и QR остаются отдельными задачами.
