# Решение по сервису адресов

Дата решения: 27.08.2026.

## Текущий этап

- Активный provider: DaData.
- Режим: бесплатный тариф для закрытого тестирования на синтетических данных.
- Переменная выбора: `GPM_ADDRESS_SUGGESTION_PROVIDER=dadata`.
- Production backend уже настроен владельцем через `/root/gpm-app-env`.
- API-ключ не хранится в Git, документации или Flutter assets.

## Проверенное production-состояние

После установки ключа и перезапуска `gpm-app-api.service` health вернулся в
норму. В кабинете логиста на синтетическом адресе DaData вернула нормализованный
адрес и координаты. Кратковременный `502` сразу после restart был переходным;
последующая проверка вернула `{"status":"ok","storage":"postgres"}`.

Перед изменением env создана закрытая копия:

```text
/root/gpm-app-env.before-dadata-20260827
```

## Перспектива

- Интеграция Яндекс Геосаджеста и Геокодера подготовлена в отдельной локальной
  ветке `feature/address-provider-switch`, но выключена.
- Переключение на Яндекс возможно только отдельным решением владельца.
- До переключения требуется подтвердить тариф, хранение координат и условия
  использования результатов Геокодера без встроенной карты.
- Ключи Яндекса пока не нужны и не должны добавляться в production.

## Неизменяемые ограничения

- Ключи провайдеров хранятся только на backend и не попадают в Git/Flutter.
- При недоступности провайдера сохраняется ручной ввод адреса.
- Дизайн и цветовая схема не изменяются; действует `DESIGN_FREEZE.md`.
