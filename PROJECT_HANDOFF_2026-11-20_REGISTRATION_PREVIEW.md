# GPM: отдельная тестовая регистрация рабочего — 20.11.2026

## Результат

Опубликована отдельная анкета в стиле действующего приложения:
https://app.gpmbot.ru/registration-preview/

Обычный вход не ведет через анкету. Кнопка «Заполнить пример» сохраняет синтетические ответы через сервер, затем открывает проверку ответов. Завершение требует отдельного нажатия.

В девяти ответах: телефон, территории, имя, фамилия, отчество, дата рождения, гражданство РФ, ремни, инструменты. Ответы сгруппированы в пять экранов. Есть итоговая карточка, изменение каждого ответа, возврат и подтвержденный перезапуск. Выбор только района разрешен; город района показан явно. Ответ «Нет» сохраняется как false. Возраст проверяется сервером, порог 18 лет, часовой пояс Europe/Moscow.

## Согласованный тестовый режим

Владелец разрешил отдельный тест до подключения к рабочей регистрации и потребовал серверное сохранение. Три решения отложены: вход по телефону, источник территорий, обязательность отчества.

Поэтому версия preview-1 использует тестовый код 123456 без SMS, серверный тестовый справочник (Москва, Санкт-Петербург и два района), необязательное отчество. Эти ограничения видны в форме. Использовать вымышленные данные.

Создаются только тестовые профили с ID preview_..., profile_active=false. Они не дают входа в GPM, доступа к заказам, сообщениям или выплатам. Рабочие учетные записи, JWT, роли и профили не изменены. Подключение аккаунта, настоящего подтверждения телефона, восстановления доступа, каналов/уведомлений, правил и документов — следующий согласованный этап, не часть этого выпуска. Вся универсальная спецификация как рабочая интеграция еще не реализована.

## Хранение и контракт

Работа выполнена только на собственных серверах приложения GPM.
API: https://app-api.gpmbot.ru/app-api/registration-preview
Хранилище — отдельная приватная SQLite на backend GPM; настройка определена в коде модуля.
Только таблицы preview_sessions, preview_profiles, preview_events. Каталог 700, файл 600; игнорируется Git. Обновлений схемы рабочей PostgreSQL нет.

В браузере сохраняются только ID сессии и секрет доступа; ответы находятся на сервере. Повторное открытие в том же браузере продолжает черновик. Перенос на другое устройство и восстановление после очистки браузера пока не подключены: для этого нужен согласованный вход. Секрет нельзя помещать в публичные ссылки, Git или журналы.

Черновик действует 30 дней с последнего изменения. Проверки выполняются на сервере. Есть ревизии против устаревших действий, транзакция завершения, уникальность телефона внутри тестовых профилей, идемпотентность, ограничения запросов и попыток кода. Серверное доказательство кода связано с текущим номером; изменение номера его сбрасывает. Коды в этом режиме заведомо тестовые.

## Backup и откат

Штатный зашифрованный backup GPM дополнен согласованной онлайн-копией SQLite, проверкой целостности и числа строк трех тестовых таблиц. Приватные данные остаются в зашифрованном backup, ключ хранится отдельно. Старые backup проверяются прежним способом.

Откат кода выполняется штатным способом из сохраненного выпуска. Тестовое хранилище сохраняется отдельно; откат кода не требует сброса рабочей PostgreSQL или удаления анкет. Полный restore рабочей БД без отдельного поручения не выполнять. Внутренние адреса, пути хранения и частные материалы в этот публичный контекст не включены.

## Ручная приемка и следующий шаг

Проверить новую ссылку на телефоне и компьютере: телефон и код 123456; несколько территорий и только район; пустое необязательное отчество; возраст; все три ответа «Нет»; редактирование всех ответов; обновление страницы после сохраненного шага; итоговое подтверждение. Для быстрого просмотра использовать «Заполнить пример». Ручная приемка владельцем еще не пройдена; тесты и снимки ее не заменяют.

После визуальной приемки согласовать три производственных решения и план связи с рабочими профилями. Реальные аккаунты и связанные жизненно важные компоненты подключать только отдельным согласованным этапом.

Сохранен прежний объем: у грузчика «Сегодня / Завтра / Все», по умолчанию «Сегодня»; у логиста период публикации; чаты без новых фильтров. Ручная приемка трех ролей, остальные этапы замечаний и решение QR/окончательной приемки не объявлены закрытыми.

CRM и TS не затронуты. Основную CRM разрешено только читать при отдельном аудите; ее выпуск не разрешен. Очистка заявок не разрешает удалять аккаунты, auth, таблицы, backup или инфраструктуру. Debt-off, cron/scheduler и письма TS не менялись. Удаленная работа через GitHub/Actions и собственные серверы GPM; локальных исходников, SDK или архивов на C: не создавалось.
