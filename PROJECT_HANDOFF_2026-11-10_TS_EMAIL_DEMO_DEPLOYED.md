1. Владелец входит на https://ts.workstaffcrm.ru обычным способом и получает
   код на свой email. Реальная доставка владельцу и браузерный вход еще не

   синхронизация, ставка, права логиста, повторы без дублей. Не считать пройденным
   по одному HTTP 200. Не запускать живой sync как smoke и не менять произвольные
   реальные заявки; сначала установить предназначенные для приемки объекты.

   сохранить; не возвращать исключенные исправления автоматически.

## Границы систем и обязательные ограничения

Основную CRM разрешено только читать для сверки: без правок файлов/настроек/БД,
запуска Laravel/заданий/миграций/sync и переноса ее данных/секретов. Выпуск на
основную требует отдельного явного согласования после тестов. В этой итерации
основная не читалась и не менялась. Соседний test и общие FPM/master/cron/MySQL
не менялись и не перезапускались. Только TS; public/storage наружу не обходили.

Очистка заявок не разрешает удаление таблиц/схемы/кода/аккаунтов/профилей/auth/
приглашений/аудита/конфигурации/секретов/backup/инфраструктуры, включая репетицию.
Для жизненно важных объектов нужны отдельная задача, перечень, последствия,
план восстановления и явное согласование. Ранее разрешенные три backup-дубликата
уже удалены по прежней задаче; это не разрешает новых удалений. В этом выпуске
auth-контроллер/проверки, аккаунты, схема и данные не менялись; заменялся только
почтовый путь внутри существующего метода согласно уточнению владельца.
Секреты/пароли/OTP/JWT/plaintext backup/частные исходники в Git и логи не помещать.
