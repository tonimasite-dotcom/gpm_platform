# Запуск логиста и исполнителя: решение от 24.11.2026

## Решение владельца

Первый этап запуска приложения — логист и исполнитель.
Логиста пока заводить вручную. При регистрации логиста автоматически
создавать его в CRM не нужно. Исполнитель должен попадать в CRM при регистрации.
Клиента пока отложить до готовности всего приложения; автоматическое создание
клиента в CRM сейчас не подключать. Это приоритет работ, а не поручение удалять
существующие роли, аккаунты или интерфейсы.

## Что работает сейчас

Проверен опубликованный код main на 5e049c958f9f68632ab55635b19ef11d7a290d41:
app/registration_preview_crm.py и worker-link/GpmPreviewWorkerSync.php,
GpmPreviewWorkerPolicy.php.

После полного завершения отдельной тестовой анкеты registration-preview
исполнитель попадает в рабочие TS при ближайшем ежеминутном обмене.
Это не создание карточки при открытии анкеты или вводе кода.
Если по полному нормализованному телефону есть единственный рабочий,
сохраняется связь с ним; иначе создается тестовая карточка с ролью loader.
Дубли, конфликт роли и неоднозначный филиал требуют разбора.
Существующие карточки не перезаписываются, повтор не должен создавать дубль.
Клиентов и логистов этот обмен не создает.

Код 123456 — тестовый. Анкета не создает рабочий аккаунт/JWT GPM.
Реальная SMS-регистрация и полная карта полей еще не подключены.
Не представлять тестовый обмен как завершенный рабочий запуск.

## Продолжение

1. Завершить ручную приемку анкеты исполнителя и его карточки TS владельцем.
2. Продолжать рабочую регистрацию исполнителя и необходимые сценарии
   логиста/исполнителя в согласованном порядке. Логист — ручное заведение.
3. Перед рабочей регистрацией определить SMS и необходимые поля/связь аккаунта.
   Не подменять SMS общим тестовым кодом. Клиента не включать в первый этап.
4. Не повторять готовый выпуск и не создавать дополнительные пробные карточки
   без необходимости. Не возвращать снятую панель табеля TS.

## Проверки и границы

Изменены только документы. Код, данные, настройки, серверы и схема не менялись;
новый выпуск и backup для этой фиксации не запускались. Ручная приемка не заявлена
пройденной. Предыдущие успешные deployment 45235563106 и backup 45234021155
подтверждены через GitHub API в этой сессии; это не новый backup.
Вход GitHub CLI восстановлен через системное хранилище Windows, права записи
в репозиторий проверены. Секреты и данные пользователей в документы не включены.

Основная CRM не затронута; ее изменения требуют отдельного согласования.
Жизненно важные компоненты, аккаунты, авторизация, аудит и backup не затронуты.
Очистка заявок не разрешает удалять схему, аккаунты, настройки и инфраструктуру.
Общая модернизация TS не возобновляется. debt-off, деловую почту и общие
scheduler/очереди TS не включать; обычные email-коды входа сохранить.
Не размещать среду GPM на серверах CRM. Работать через GitHub/Actions
без новых локальных копий проекта, SDK, зависимостей и сборок на C:.
