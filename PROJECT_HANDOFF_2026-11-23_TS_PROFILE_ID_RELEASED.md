# Поле ID в профиле TS опубликовано — 23.11.2026

Владелец отдельно согласовал одну необязательную колонку `users.gpm_app_crm_id` и выпуск TS. Применена только целевая миграция, установлен проверенный пакет. [PR #25](https://github.com/tonimasite-dotcom/gpm_platform/pull/25) слит: код `9f40bb78e2144a6f54f03c088e2d4f522e20be94`, merge `dbde1229107a1785a869603ff57be8e6b937231c`.

В TS поле «ID в приложении» доступно для ролей «Логист» и «Администратор»: в своем профиле под email и в карточке пользователя. Значение вводится вручную, проверяется через существующий read-only lookup GPM и подставляется при отправке заявки. Его можно очистить. Существующие профили автоматически не заполнялись. CRM не создает аккаунты GPM и не выдает ID. Корпоративные ID выдаются при регистрации в приложении по доверенному приглашению; у сторонних логистов приложения ID и карточки ID нет.

Свежая закрытая резервная копия проверена по SHA-256, gzip и завершению SQL; полное восстановление этой копии не выполнялось. До выпуска пройдены 55 PHP-проверок, проверки ролей/интерфейса, изолированной MySQL-миграции, сборки и отката. CI кода успешен. После установки совпали хеши файлов и assets по HTTPS, подтверждены новая колонка, загрузка helper, рабочий read-only lookup GPM и отказ неавторизованным запросам. Учетные данные и роли пользователей сохранены, защищенные настройки и cron совпали. Подробные квитанции и доступы остаются закрытыми.

Остается ручная визуальная приемка владельца в браузере: обновить страницу TS, открыть профиль или карточку логиста/администратора, проверить поле и сохранение своего ID. При необходимости откатывать код, сохраняя колонку и введенные ID; общий набор миграций и полное восстановление БД для отката кода не запускать. Прежнюю выдачу #1 не повторять.

Основная CRM и GPM этим выпуском не менялись. Основную CRM не менять без отдельного явного согласования. Не удалять аккаунты, профили, авторизацию, схемы, аудит, конфигурации, backup и инфраструктуру; изменение таких компонентов требует отдельной задачи, оценки последствий, плана восстановления и согласования. Пароли, телефоны, роли, номера и действующий обмен сохранены. Дебиторку, деловую почту, scheduler и очереди TS не включать; обычные email-коды сохранить. Общую модернизацию TS не возобновлять. Работать без локальных исходников, SDK, сборок и архивов на клиентском ПК; персональные данные, секреты и служебные локаторы в публичный Git не добавлять.
