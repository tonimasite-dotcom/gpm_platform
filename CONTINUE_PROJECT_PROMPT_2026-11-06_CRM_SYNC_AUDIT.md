# Продолжение GPM: аудит синхронизации CRM, 06.11.2026

Прочитай `AGENTS.md`, `README.md`, `PROJECT_HANDOFF_2026-11-06_CRM_SYNC_AUDIT.md`
и `integrations/workstaff-test-crm/README.md`.

Активная задача: проверить замечание о несинхронизированных изменениях CRM
после принятия заказа логистом и продумать аккуратное исправление.
Сделан read-only аудит, runtime и данные не менялись. Подготовлен конкретный
план в handoff. Владелец подтвердил: только ts.workstaffcrm.ru. Решение отложено
до ответов коллег о заявках, созданных в приложении, направлениях обмена и
редактируемых полях/ролях CRM-заказов. Ждать, пока владелец вернется с ответами;
не реализовывать предложенный объем и не запрашивать согласование заново до них.
Не считать подтверждение домена согласием на все записи и расширение интеграции.

Подтверждено: в ts включен gpm-crm-sync-v1, токен/API действуют, отдельный cron
раз в минуту работает, 3 runtime-файла совпадают с репозиторием. 16 sync-tests
прошли. Активных tagged/untagged Workstaff-заказов в GPM сейчас нет. Старая
привязка 005/26 (ts ID 56797) возвращает 404: GPM-заказ отсутствует, ts-заказ
существует. Последний успешный обмен 15.10, cron теперь пишет deferred: 1.
Не удалять state, не восстанавливать/перепубликовывать/привязывать автоматически.

Найдены реальные пробелы: открытые списки/карточки не обновляются сами;
редактор отправляет всю форму. На временной БД воспроизведено затирание
свежего CRM-адреса сохранением старой GPM-формы с правкой только описания.
Предложено: фоновое чтение видимых экранов без потери ввода и устаревших ответов;
только измененные поля; транзакционная защита устаревшего сохранения и конфликт
для одного поля; прежние роли/закрытые заказы/процесс GPM сохранить.
Правило приоритета GPM в существующем CRM merge не менять молча.

Live-приемка обмена потребует предоставленной связанной заявки либо отдельно
согласованной синтетической пары с перечнем записей/восстановлением значений.
Агент не менял рабочие заказы, не запускал gpm:sync-orders вручную, не создавал
сессии клиентов и не менял инфраструктуру. Read-only скрипт/лог в `.tmp/crm-sync-*`.

Последний release: frontend `242f4b7`, backend `f63745a`; мобильные кнопки
владелец подтвердил. Документация может иметь новый SHA, это не новый deployment.
Для GitHub CLI нужен доступ к Windows keyring вне sandbox. Read-only SSH ts
проверен через известный host key; не выводить ключи, токены, env и business values.

Строгое правило владельца от 06.11.2026: работать только с `ts.workstaffcrm.ru`.
Основную CRM вообще не трогать до завершения всех тестов и проверки синхронизации;
переход к ней требует отдельного явного согласования. Задача по GPM не разрешает
менять основную CRM.
В этом аудите основная CRM не затронута, тестовая CRM только читалась.

Очистка заявок не разрешает удаление таблиц, схемы, кода, аккаунтов, профилей,
авторизации, приглашений, аудита, конфигурации, секретов, backup и инфраструктуры.
Для изменения жизненно важных компонентов нужны отдельная задача, перечень
объектов, оценка последствий, план восстановления и явное согласование.
Жизненно важные компоненты и рабочие данные в аудите не менялись.
Секреты, пароли и незашифрованные backup не публиковать в Git и логах.
